# Helio

Helio is a four-stage agentic delivery framework spanning the path from
business request to running system. The four stages are **Capture**,
**Build**, **Promote**, and **Operate**. Helio is opinionated about the
front of the lifecycle — its Capture stage carries a heavy admissibility
burden — and equally opinionated about what is required to put a system
into production and to run it.

Helio is intentionally silent on the back of the lifecycle. It does not
prescribe how a system is withdrawn from service. The framework's
authors take the view that the post-Operate transition is an
organisational question rather than a delivery-framework question and
explicitly defer it to whatever change-management or service-management
process the adopting organisation already operates.

## Stage map

| Helio stage | Surface area |
| --- | --- |
| Capture | Demand validation, value framing, scope shaping |
| Build | Engineering execution (deferred to underlying engineering practice) |
| Promote | Release evidence, independent validation, control state |
| Operate | Persistent operational obligations and stewardship |

## Status

1.4. In production at three regulated firms; under evaluation at two
others. The framework's silence on retirement has been raised by adopters
as a known scope gap that Helio's authors do not currently plan to close.
